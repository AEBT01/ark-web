# 跨页面任务（cross-page）

## 核心原则
**每个标签页都是可独立观察的目标，切换活动标签页不是读取它的前提。**
用户可能正在看别的页面 —— 把他的标签页切走是打扰，也是旧式自动化工具的坏习惯。

## 做法
1. **开页**：`open_tab {url}` 打开新页面（新标签页默认在后台，不影响用户）。
2. **列目标**：`list_tabs` 或 `cdp_targets` 拿到各页面的 target。
3. **定向读**：内核类工具（`cdp_eval`、`cdp_screenshot`、`cdp_performance`）都支持 `target_id` 参数 —— 显式传它，就在那个页面上执行，**不激活**。
4. **语义层跟随任务视野**：`semantic_find` 等默认作用于任务的工作页；要读别的页时用内核工具或 `activate_tab` 后再切回。
5. **收尾**：临时开的对比页任务结束后可 `close_tab`（不确定时保留并在答复里说明）。

## 后台页面的技术细节
- 后台标签页视口是 0×0，系统会用 CDP 视口覆盖自动保障截图与坐标操作 —— 你不需要（也不应该）为了"看清"而激活标签页。
- 若某工具明确报"页面未渲染"，先 `wait_load`，仍失败再考虑 `activate_tab`，用完尽快切回。

## 典型形态
- **对比**：开 B 页 → 各自提取 → `finish` 给对比表。
- **搬运**：读 A 页的规格 → 开 B 页 → `semantic_fill` 填入 → 提交前请示。
- **汇合**：多个列表页各取前 N 条 → 合并去重 → `write_file` 落盘。
