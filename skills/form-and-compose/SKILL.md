# 表单与提交（form-and-compose）

## 流程
1. **盘点**：`semantic_find {query:"表单 输入"}` 或 `query_all {selector:"input,textarea,select"}` 列出全部字段。
2. **逐项填**：`semantic_fill` 按 label 定位（"昵称""手机号"）。一个字段一次调用，填完不需要每项都核实。
3. **提交前自查**：重读一遍已填内容（`evaluate` 读 input value 或重新 query），确认没有空必填项、格式错误。
4. **提交**：`semantic_click` 点提交/发送/下单按钮。**提交类按钮都是高风险动作，会被系统拦截并请示用户 —— 这是预期**。
5. **核实**：提交后看页面反馈（成功提示、跳转、列表新增一条），如实报告。

## 纪律
- **绝不自填**：密码、支付信息、验证码、身份证号。遇到这类字段停下来 `finish` 说明需要用户亲自填写。
- 用户只给了部分信息时，能推断的填上并在答复说明假设；不能推断的留空并明确列出还缺什么。
- 下拉框用 `select_option`；日期控件通常要点开面板，用 snapshot 看结构再操作。
- 提交被拦截且用户批准后：**只重做被拦截的那一步**（点提交），前面已填的内容不要重填 —— 重填可能清空或造成重复提交。

## 失败处理
- 提交后表单仍显示且出现红色校验提示 → 读提示文字，修正对应字段，再提交（新的一次提交会再次请示）。
- 点击无反应且 console 有报错 → `troubleshooting` 技能。
- 验证码出现 → 停止，如实说明。
