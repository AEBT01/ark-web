# 数据提取（data-extraction）

## 标准流程
1. **取样**：先 `semantic_find` 或 `read_text` 看数据长什么样（字段名、格式、数量级）。
2. **定界**：确认数据边界 —— 一页有多少条？有没有分页/加载更多？
3. **批量读**：逐条 `semantic_read`，或 `query_all` 一次性抓同构节点。
4. **产出**：在 `finish.answer` 里给结构化结果。用户要文件时用 `write_file` 落盘（CSV/Markdown/JSON），并在答复里给路径。

## 保真规则
- **逐条对齐**：每条记录的字段要来自同一条数据的读取，不要从记忆里拼。
- **数字原样保留**：价格"¥1,299.00"不要改写成"1299"，单位、小数位照抄。
- **读不到就标"未获取"**：不要用猜测值补齐表格 —— 一个编造的字段会污染整份结果。
- 条数多时（>30 条）在答复开头给出总数与截断说明，正文给前 N 条 + 完整内容写文件。

## 分页与加载
- 有"下一页/加载更多"：`semantic_click` 翻页 → 每页重复批量读 → 合并。
- 无限滚动：`scroll {x,y}` 触发加载，`wait_for` 等新内容，直到条数不再增长。
- 分页上限：默认最多翻 20 页，超出就在答复里说明"已取前 20 页，其余未读"。

## 大页面
- 单元很多时 `semantic_find` 的 top_k 控制 候选数；`read_text` 有长度上限，长文用 `semantic_read` 按 id 取段。
- 超长读取结果会被系统截断并给出取回方式（spill 文件路径），需要完整内容时按提示取回，不要凭截断的预览下结论。

## 输出格式约定
- 表格用 Markdown 表；CSV 用逗号并给 `write_file` 的绝对路径；JSON 用代码块。
- 表头即字段名，保持与页面用语一致（用户要能对回页面）。
